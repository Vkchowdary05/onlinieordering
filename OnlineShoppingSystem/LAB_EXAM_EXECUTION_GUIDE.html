📖 Core Docker Concepts for Lab Exam Viva

1. What is Docker and Containerization?

Containerization is an operating-system-level virtualization method for deploying and running distributed applications without launching an entire virtual machine (VM) for each app. Containers share the host OS kernel and isolate user spaces, making them lightweight and fast to start (seconds vs minutes for VMs).

2. Docker Image vs Docker Container

  • Docker Image: An immutable, read-only template built from a Dockerfile. It contains the application code, runtime engine, libraries, and environment variables.
  • Docker Container: A running, writeable instance of an image. You can start, stop, pause, move, or delete containers using Docker CLI.

3. Multi-Stage Docker Builds (Crucial Exam Concept)

A multi-stage build uses multiple FROM statements in a single Dockerfile. Each FROM instruction can use a different base image and begins a new build stage.

Why Multi-Stage Builds Matter:

They separate the heavy build environment (which needs compilers, TypeScript, Vite, npm dependencies) from the minimal production runner (which only needs the compiled static files or small Node runner). This drastically reduces image size (from ~1GB to ~65MB-90MB), eliminates build tools from production, and increases container security.

💻 Docker CLI Command Syntax Explained

1. Creating a Docker Image (`docker build`)

docker build [OPTIONS] PATH | URL | -
  • -t, --tag name:tag: Assigns a human-readable name and version tag to the image (e.g. medicare-hospital-app:latest).
  • -f, --file string: Specifies the path to an alternate Dockerfile (defaults to ./Dockerfile).
  • --no-cache: Forces Docker to rebuild all layers from scratch without using cached intermediate layers.
  • . (period at end): The build context. Instructs Docker to send the files in the current directory to the Docker daemon.

2. Creating & Running a Docker Container (`docker run`)

docker run [OPTIONS] IMAGE [COMMAND] [ARG...]
  • -d, --detach: Runs the container in the background (detached mode) and prints the Container ID.
  • -p, --publish host_port:container_port: Maps a network port on the host to a port inside the container. E.g. -p 3002:80 forwards requests to host port 3002 into Nginx port 80 inside the container.
  • --name string: Assigns a memorable name to the container (e.g. onlineshopping-app) instead of random generated words.
  • --rm: Automatically removes the container when it exits/stops (great for temporary test runs).
  • --restart unless-stopped: Automatically restarts the container if it crashes or the Docker daemon reboots.
  • -e, --env KEY=VALUE: Injects environment variables at container launch.

3. Inspecting, Managing & Stopping Containers

# List running containers
docker ps

# List ALL containers (including exited/stopped)
docker ps -a

# View container output logs (follow in real time)
docker logs -f <container_name>

# Check resource usage (CPU, RAM, Network I/O)
docker stats

# Execute an interactive shell inside a running container
docker exec -it <container_name> /bin/sh

# Stop and delete a container
docker stop <container_name>
docker rm <container_name>
# Or force stop and remove in a single command:
docker rm -f <container_name>

# Delete a Docker image
docker rmi <image_name>:<tag>

🔍 Selenium Test Automation Deep Dive

1. Element Locators (`By`)

Selenium WebDriver uses the By strategy class to identify HTML elements in the DOM:

Locator Strategy Python Syntax Example When to Use
By.ID driver.find_element(By.ID, "checkout-name") Fastest and most unique locator when IDs exist.
By.CSS_SELECTOR driver.find_element(By.CSS_SELECTOR, '[data-testid="add-to-cart-btn"]') Industry standard for testing frameworks; uses data-testid.
By.XPATH driver.find_element(By.XPATH, "//*[contains(text(), 'Order Details')]") Locates elements by visible text or complex parent/child hierarchy.
By.NAME driver.find_element(By.NAME, "email") Form inputs with standard HTML name attributes.

2. Explicit Waits (`WebDriverWait`) vs Hard Sleep

Examiner Viva Tip: Why avoid time.sleep() in automation?

time.sleep(5) pauses the test execution unconditionally, making the test suite slow and brittle. Instead, use Explicit Waits (WebDriverWait + expected_conditions). Explicit waits poll the DOM every 500ms and continue immediately once the condition is met (e.g. element is clickable), keeping tests fast and resilient.

from selenium.webdriver.common.by import By
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

# Initialize explicit wait with a 10-second maximum timeout
wait = WebDriverWait(driver, timeout=10)

# 1. Wait until button is clickable, then click
login_btn = wait.until(
    EC.element_to_be_clickable((By.CSS_SELECTOR, '[data-testid="btn-login-submit"]'))
)
login_btn.click()

# 2. Wait until greeting text is visible in DOM
greeting = wait.until(
    EC.visibility_of_element_located((By.CSS_SELECTOR, '[data-testid="patient-greeting"]'))
)
assert "Sarah" in greeting.text

🛠️ Common Lab Exam Errors & Fixes

Error 1: "Bind for 0.0.0.0:3000 failed: port is already allocated"

Cause: Another process or container is already using port 3000.

Fix:

# Check all running docker containers
docker ps

# Stop the conflicting container
docker stop <conflicting_container_name>

# If a Windows host process is using the port, find and kill it:
Get-NetTCPConnection -LocalPort 3000 | Select-Object OwningProcess
Stop-Process -Id <PID> -Force

Error 2: "failed to connect to docker API / daemon is not running"

Cause: Docker Desktop background service is stopped.

Fix:

# Start Docker Desktop from PowerShell
Start-Process "C:\Users\papas\AppData\Local\Programs\DockerDesktop\Docker Desktop.exe"

# Wait 15-20 seconds, then verify
docker ps

Error 3: "No module named pytest / selenium"

Cause: Python packages are missing in your environment.

Fix:

python -m pip install selenium pytest pytest-html webdriver-manager
